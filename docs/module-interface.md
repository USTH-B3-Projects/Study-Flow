# StudyFlow Module Interface

This document defines the public interfaces for the JavaScript service modules. It is the shared contract for implementation and integration. Function names, parameters, return types, and stored fields should not be changed without informing the team.

## General conventions

- All public functions listed here must be exported from their service file.
- `studentId` is entered by the student and is the unique account/login identifier.
- `courseId` and `taskId` are generated by the system.
- A lookup function returns `null` when the requested object does not exist.
- A command returning `boolean` reports whether the operation succeeded.
- `estimatedDuration` remains `null` when omitted. A fallback `effectiveDuration` of 3 hours is used only during priority calculations.
- `completionStatus`, `displayStatus`, `isOverdue`, scores, remaining workload, and warnings are derived values and must not be stored in task records.
- Dates are ISO 8601 strings, durations are measured in hours, and progress is stored as one of `0`, `25`, `50`, `75`, or `100`.

## Shared return type

Authentication commands return an `OperationResult`:

```js
{
  success: boolean,
  message: string,
  student: Student | null,
  recoveryCode?: string
}
```

`recoveryCode` is returned only after successful registration or password reset so it can be shown once. It must never be stored directly.

## `storageService.js`

Provides the common interface for reading and writing StudyFlow data in `localStorage`.

| Function | Parameters | Expected return | Responsibility |
| --- | --- | --- | --- |
| `initStorage()` | None | `void` | Initialize missing StudyFlow storage keys with their default values. |
| `getData(key)` | `key: string` | `any` | Read and parse data stored under a key. |
| `saveData(key, data)` | `key: string`, `data: any` | `void` | Convert data to JSON and save it under a key. |
| `removeData(key)` | `key: string` | `void` | Remove data stored under a key. |

### Storage keys

| Key | Initial value | Purpose |
| --- | --- | --- |
| `studyflow_users` | `[]` | Stored student records. |
| `studyflow_current_user` | `null` | Student ID of the currently authenticated student. |
| `studyflow_courses` | `[]` | Course records. |
| `studyflow_tasks` | `[]` | Task records. |

## `authService.js`

Manages registration, authentication, password recovery, and the current login session.

| Function | Parameters | Expected return | Responsibility |
| --- | --- | --- | --- |
| `register(studentName, studentId, password, confirmPassword)` | 4 strings | `Promise<OperationResult>` | Validate the input, create a student record, generate and store `recoveryCodeHash`, and return the original recovery code once. |
| `login(studentId, password)` | 2 strings | `OperationResult` | Authenticate a student and save the current session. |
| `resetPassword(studentId, recoveryCode, newPassword, confirmPassword)` | 4 strings | `Promise<OperationResult>` | Validate the recovery code, update the password, invalidate the old code, and return a newly generated recovery code once. |
| `logout()` | None | `void` | End the current session by removing `studyflow_current_user`. |
| `getCurrentUser()` | None | `Student \| null` | Return the authenticated student or `null` if no valid session exists. |

## `courseService.js`

Manages course records belonging to students.

| Function | Parameters | Expected return | Responsibility |
| --- | --- | --- | --- |
| `createCourse(course)` | `course: object` | `Course` | Validate the input, generate `courseId`, and create a course. |
| `getCoursesByStudentId(studentId)` | `studentId: string` | `Course[]` | Return all courses belonging to a student. |
| `getCourseById(courseId)` | `courseId: string` | `Course \| null` | Return one course by ID. |
| `updateCourse(courseId, data)` | `courseId: string`, `data: object` | `Course \| null` | Update only `courseName` and/or `color`. |
| `deleteCourse(courseId)` | `courseId: string` | `boolean` | Delete a course and its related tasks. |

### Course creation input

The `course` object contains:

- `studentId`
- `courseName`
- `color` (optional; defaults to `null`)

The service generates only `courseId`. It must not add creation metadata that is absent from the data contract.

## `taskService.js`

Manages task CRUD operations, progress updates, completion, and task queries.

| Function | Parameters | Expected return | Responsibility |
| --- | --- | --- | --- |
| `createTask(taskData)` | `taskData: object` | `Task` | Validate the input, generate `taskId` and `createdAt`, and create a task record. |
| `getTasksByStudentId(studentId)` | `studentId: string` | `Task[]` | Return tasks from all courses belonging to the student. |
| `getTasksByCourseId(courseId)` | `courseId: string` | `Task[]` | Return all tasks in one course. |
| `getTaskById(taskId)` | `taskId: string` | `Task \| null` | Return one task by ID. |
| `updateTask(taskId, data)` | `taskId: string`, `data: object` | `Task \| null` | Update only permitted task fields and preserve `taskId`, `courseId`, and `createdAt`. |
| `deleteTask(taskId)` | `taskId: string` | `boolean` | Delete one task. |
| `updateTaskProgress(taskId, currentProgress)` | `taskId: string`, `currentProgress: number` | `Task \| null` | Update progress using an allowed progress value. Status remains derived rather than stored. |
| `markComplete(taskId)` | `taskId: string` | `Task \| null` | Set `currentProgress` to `100`. |
| `getOverdueTasks(studentId)` | `studentId: string` | `Task[]` | Return incomplete tasks whose deadlines have passed from all courses belonging to the student. |

### Task creation input

The `taskData` object contains:

- `courseId`
- `taskName`
- `description` (optional; defaults to `""`)
- `deadline`
- `importance` (defaults to `"medium"`)
- `estimatedDuration` (optional; remains `null` when omitted)
- `currentProgress` (defaults to `0`)

The service generates `taskId` and `createdAt`. It stores no derived score, status, remaining workload, or warning field.

## `smartService.js`

Calculates derived task values, ranks incomplete tasks, provides the next-task recommendations, and detects workload risk.

| Function | Parameters | Expected return | Responsibility |
| --- | --- | --- | --- |
| `calculateUrgencyScore(deadline)` | `deadline: string \| Date` | `number` | Calculate urgency from time until the deadline. |
| `calculateImportanceScore(importance)` | `importance: string` | `number` | Convert an importance level into its numeric score. |
| `calculateRemainingWorkload(estimatedDuration, currentProgress)` | `number \| null`, `number` | `number` | Use `estimatedDuration`, or a 3-hour effective duration when it is `null`, to calculate remaining work. |
| `calculateWorkloadScore(remainingWorkload)` | `remainingWorkload: number` | `number` | Convert remaining workload into its numeric score. |
| `calculatePriorityScore(task)` | `task: Task` | `number` | Calculate `0.5 * urgency + 0.3 * importance + 0.2 * workload`. |
| `rankTasks(tasks)` | `tasks: Task[]` | `Task[]` | Exclude completed tasks and return the rest in ranking order without storing calculated values. |
| `getGlobalRecommendation(studentId)` | `studentId: string` | `Task \| null` | Return the highest-ranked incomplete task across all of the student's courses. |
| `getLocalRecommendation(courseId)` | `courseId: string` | `Task \| null` | Return the highest-ranked incomplete task within one course. |
| `getWorkloadWarning(tasks)` | `tasks: Task[]` | `Task[]` | Return non-completed, non-overdue tasks that meet the workload-warning rule and have a user-provided duration. |

### Ranking order

Use the following comparison order:

1. Priority score: descending.
2. Deadline: ascending.
3. Importance score: descending.
4. Created time: ascending.

### Workload warning rule

The web version does not collect available study time. A task receives a workload warning only when:

- it is not completed;
- it is not overdue;
- the user provided `estimatedDuration`; and
- `(urgencyScore >= 80 && workloadScore >= 60)` or `(urgencyScore >= 60 && workloadScore >= 80)`.

An overdue task is displayed as overdue instead of receiving a workload warning. The warning must not claim that the student lacks enough available study hours.

## Module dependencies

| Module | May use |
| --- | --- |
| `authService.js` | `storageService.js` |
| `courseService.js` | `storageService.js` |
| `taskService.js` | `storageService.js`; course data when filtering by student |
| `smartService.js` | `taskService.js` and task data |

Page scripts and UI components may call service functions, but service modules must not directly manipulate HTML elements.
